# Baseline audit

Baseline: eba7adc, module github.com/pavel1337/lxcer, Go 1.14. All eight Go source files, config, README and todo were inspected. Original author and history are retained; no license file exists, so redistribution licensing requires the author's clarification before publication.

The original main.go contains duplicated sequential and channel pipelines. container.go wraps snapshot, publish, export and compression; host.go duplicates remote orchestration. image.go deletes images; restic_repo.go wraps backup/check/restore. config.go uses global flags and YAML; util.go provides membership checks.

Confirmed reproduction: `go test ./...` originally reports no tests. Added TestRegressionStoppedContainersSelected fails: selected 1, expected 2. filterContainers rejects all states except 103. Local entry points never inspect -container. Pipeline errors are logged or dropped, including failed upload forwarding an item to deletion. No aggregate error reaches main. Zero workers can silently drain no work. Cleanup enumerates all local instances/images without ownership checks. Snapshot/image aliases and filenames are shared by instance name, causing cross-host and concurrent collisions. Remote publish is followed by local image export without explicit transfer. Archives are removed before restore validation. Restore launches immediately with inherited networking. No manifest or checksum exists.

Credentials are plaintext YAML; subprocess output can reveal secrets. Commands use argv (good), but timeouts, signal recovery and locks are absent. Config path argument is ignored in favor of a global. Restore list malformed lines are silently skipped. Compression consumes all CPUs per worker. Full intermediate archives increase disk demand. Restic checks are commented out; no snapshot identity or content verification exists. There is no CI, release workflow, test suite or compatibility evidence.

Replacement architecture: bounded scheduler -> host capability discovery -> per-instance locked job -> strategy -> per-destination Restic verification -> persisted terminal state -> ownership-aware cleanup. Linux flock releases on crashes. Private atomic JSON manifests are a durable catalog and are included with each upload; receipts remain locally and repository tags permit rediscovery after local catalog loss. Failure staging is retained. Restore defaults to stopped instances; test restores require a dedicated target host and an explicitly isolated profile.
